# 우사기 랭귀지 컴파일러 1.1.0

우사기 소스를 Python으로 분석하고 C11로 변환한 뒤, Clang으로 Windows 실행 파일을 만듭니다. 세 반응 분기·박자 반복·마지막 조건 반복, 중괄호 없는 함수, 문자열과 숫자 입출력을 지원합니다. C는 중간 출력이며 우사기 문법·범위·타입 규칙은 자체 분석기가 처리합니다.

언어 표준은 상위 폴더의 [USAGI_LANGUAGE_SPEC.md](../USAGI_LANGUAGE_SPEC.md), 구현 기록은 [USAGI_COMPILER_PLAN.md](../USAGI_COMPILER_PLAN.md)에 있습니다. 이 문서는 실제 컴파일러 1.1.0의 사용법과 지원 범위를 설명합니다. VS Code 확장 사용법은 [usagi-vscode/README.md](../usagi-vscode/README.md)에 있습니다.

## 바로 실행하기

VS Code에서 **이 README가 있는 `usagi-compiler` 폴더**를 열고 터미널에 입력하세요. Python 3.12 이상과 설치된 Clang·MSVC·Windows SDK를 사용합니다. 별도 Python 패키지 설치나 전용 VS Code 확장은 필요하지 않습니다.

```powershell
py -m usagi run examples/input_plus_one.usagi
```

입력을 기다리면 `4`를 입력하고 Enter를 누릅니다. `5`가 출력되면 성공입니다. 프로그램은 별도의 입력 안내 문구를 출력하지 않습니다.

`py` 대신 `python`으로 설치된 Python을 실행하는 환경이라면 모든 명령의 `py`를 `python`으로 바꾸세요. 선택된 버전은 `py --version`으로 확인할 수 있습니다. 여기서 사용한 검증 환경은 Python 3.12.14입니다.

실행 파일로 빌드해 두고 다시 실행할 수도 있습니다.

```powershell
py -m usagi build examples/input_plus_one.usagi -o build/input_plus_one.exe
.\build\input_plus_one.exe
```

이 `.exe`는 현재 Windows x64 환경에서 생성하고 실행을 검증했습니다. 다른 컴퓨터에서의 배포·런타임 의존성 검증은 별도로 해야 합니다.

## 첫 프로그램

[examples/input_plus_one.usagi](examples/input_plus_one.usagi):

```text
우사기!
    얏! 하치와레: 야 뿌 야하!
    냠? 하치와레: 야 야하!
    우~라~ 하치와레: 야 하! 뿌르 야하!
!우사기
```

`얏! 하치와레: 야 뿌 야하!`는 정수 변수 `하치와레: 야`를 0으로 초기화합니다. `냠?`로 숫자를 입력받고, `우~라~`로 계산 결과를 출력합니다. `뿌르`는 1입니다. 문장은 `야하!`로 끝납니다.

프로젝트 최상위의 `main.usagi`도 새 문법으로 변경했습니다. 직접 수정하고 저장한 뒤 `py -m usagi run main.usagi`로 실행할 수 있습니다.

## 중괄호 없는 함수

```text
우나! 하치와레: 숫자 만들기
    핫! 하치와레: 야 뿌르르르.뿌르르 야하!
우~나! 하치와레: 야

우사기!
    얏! 하치와레: 야 하치와레: 숫자 만들기 우라! 우라라! 야하!
    핫! 하치와레: 야야 하치와레: 숫자 만들기 우라! 우라라! 야하!
    우~라~ 하치와레: 야 야하!
    우~라~ 하치와레: 야야 야하!
!우사기
```

`우나! 하치와레: 숫자 만들기`가 함수를 시작하고, `우~나! 하치와레: 야`가 그 함수를 닫으면서 `하치와레: 야`의 값을 반환합니다. `하치와레: 야`는 실수형이므로 함수 반환형도 실수입니다. 반환형을 따로 적을 필요가 없습니다. 호출은 `하치와레: 숫자 만들기 우라! 우라라!`입니다.

정수 변수에 넣는 첫 번째 결과는 자동으로 3이 되고, 실수 변수에 넣는 두 번째 결과는 3.2로 유지됩니다. 이 프로그램의 출력은 `3`, `3.2` 두 줄입니다.

```powershell
py -m usagi run examples/functions.usagi
```

함수명에는 매번 `하치와레:`를 붙입니다. 변수명은 `야`만 반복한 경우에만 접두사를 생략할 수 있습니다. 사용자 이름은 한글 완성형·영문·밑줄로 시작하고 뒤에는 숫자와 단어 사이 공백도 가능합니다. 함수는 메인 앞이나 뒤에 선언할 수 있습니다. 인자는 아래의 먹이기 문법을 사용합니다. 메인은 정확히 하나이며 실행은 메인에서 시작합니다. 재귀·상호 재귀와 중첩 함수는 지원하지 않습니다.

함수마다 지역 변수는 독립적입니다. 함수 안에서 다른 함수나 메인의 지역 변수에 접근할 수 없습니다. 함수 호출을 포함한 식은 왼쪽부터 평가하며 같은 함수도 호출할 때마다 실행합니다. 반환값을 버리는 단독 호출도 가능합니다: `하치와레: 숫자 만들기 우라! 우라라! 야하!`.

`!우사기`와 `우~나! 반환식`은 함수 경계 자체를 나타내므로 뒤의 `야하!`는 생략 가능합니다. 본문 안의 일반 문장에는 계속 `야하!`가 필요합니다. 일반 함수는 반환식이 필수이며, 메인의 `!우사기`에는 반환값을 적지 않습니다.

**0.1에서 변경:** 예전의 `우나!` 메인 시작과 `우~나! 야하!` 종료는 새 문법과 충돌하므로 지원하지 않습니다. 메인을 `우사기!`·`!우사기`로 바꾸고 함수 전체를 감싸던 중괄호를 제거하세요.

## 냠!으로 함수에 인자 먹이기

```text
우나! 하치와레: 더하기
    냠! 얏! 야
    냠! 얏! 야야
우~나! 야 하! 야야

우사기!
    얏! 야 하치와레: 더하기 냠! 뿌르르 냠! 뿌르르르 꿀꺽! 야하!
    우~라~ 야 야하!
!우사기
```

출력은 `5`입니다. 함수 선언에서는 이름과 본문 사이에 `냠! 자료형 이름`을 적습니다. 호출에서는 각 값을 `냠!`으로 시작하고 `꿀꺽!`으로 호출을 끝냅니다. 쉼표와 인자 괄호는 사용하지 않습니다. 매개변수 선언에는 초기값이나 `야하!`가 없습니다.

정수·실수·문자열을 지원합니다. 인자 수는 정확히 맞아야 하고 선언 순서대로 전달합니다. 계산과 매개변수형 변환은 왼쪽부터 끝내며, 모든 인자를 값으로 복사합니다. 함수 안에서 값을 바꿔도 호출자의 변수는 바뀌지 않습니다. 숫자 변환과 문자열 변환 오류는 일반 대입 규칙과 같습니다.

다른 함수 호출을 인자로 넣을 수 있습니다. 중첩 호출마다 `꿀꺽!`이 필요합니다. 인자 없는 호출은 기존 `하치와레: 함수명 우라! 우라라!`을 계속 씁니다. 기본·가변·이름 지정 인자와 재귀는 아직 지원하지 않습니다.

```powershell
py -m usagi run examples/feeding_arguments.usagi
```

## 문자열과 사용자 이름

**`하치와레!`는 문자열 자료형, `하치와레:`는 사용자 이름의 접두사입니다.**

```text
우나! 하치와레: 인사 만들기
    하치와레! 하치와레: 인사 내용 하치! 안녕, 우사기! 와레! 야하!
우~나! 하치와레: 인사 내용

우사기!
    하치와레! 하치와레: 출력 내용 하치와레: 인사 만들기 우라! 우라라! 야하!
    우~라~ 하치와레: 출력 내용 야하!
!우사기
```

결과는 `안녕, 우사기!`입니다. 함수가 문자열을 반환하면 반환형도 문자열로 추론합니다. 사용자 이름은 선언과 모든 사용 위치에서 `하치와레:`를 붙이며, **`야`, `야야`, `야야야`처럼 `야`만 반복한 변수명은 유일하게 접두사 없이 사용합니다.** 이 예외는 정수·실수·문자열 모두에 적용되며 선언·참조·대입·입력·반환식에서 지원합니다. 함수에는 적용하지 않습니다.

```text
우사기!
    얏! 야 뿌르 야하!
    핫! 야야 뿌.뿌릇 야하!
    하치와레! 야야야 하치! 안녕! 와레! 야하!
    우~라~ 야 야하!
    우~라~ 야야 야하!
    우~라~ 야야야 야하!
!우사기
```

`야값`, `야야2`, `야_`는 예외에 해당하지 않습니다. `하치와레: 야`와 `야`는 같은 변수를 가리키므로 같은 블록에서 두 표기로 각각 선언할 수 없습니다. 입출력·함수 반환까지 사용하는 예제는 `examples/short_variables.usagi`에 있습니다.

이름은 같은 줄에서 다음 문법 키워드·우사기 숫자·문자열 시작·다른 `하치와레:` 앞까지 읽습니다. 이미 시작한 이름 뒤의 `야` 반복 변수명도 별도 토큰으로 구분합니다. 단어 사이의 여러 공백·탭은 공백 하나로 취급합니다. `하치와레: 숫자 만들기`와 `하치와레: 숫자만들기`는 서로 다른 이름입니다.

문자열은 `하치!`부터 같은 줄의 첫 `와레!`까지입니다. 내부의 `야하!`, `!우사기`, `하치와레:` 등은 그대로 글자가 됩니다. 표식과 내용 사이의 ASCII 공백은 양쪽에서 각각 최대 하나씩 구분용으로 제외합니다. 따라서 `하치! 안녕 와레!`와 `하치!안녕와레!`는 같습니다. 추가 공백은 보존하며, `하치! 와레!`는 빈 문자열입니다.

문자열은 UTF-8 기준 최대 4,095바이트, NUL 제외입니다. 대입과 반환은 값을 복사하므로 함수가 끝나거나 원본 변수에 다시 대입해도 이미 받은 값은 유지됩니다. 문자열 연결, 숫자와 문자열 사이의 자동 변환, 여러 줄 리터럴, 일반 이스케이프 및 내용 안에 `와레!`를 넣는 표기는 아직 지원하지 않습니다. 역슬래시는 그대로 출력합니다.

```powershell
py -m usagi run examples/strings.usagi
py -m usagi run examples/string_input.usagi
```

첫 예제는 인사를 두 줄 출력합니다. 두 번째는 한 줄을 입력받아 그대로 출력합니다. 문자열 입력은 따옴표 표식 없이 일반 글을 입력하며, 앞뒤 공백과 빈 줄을 보존합니다. 이전 문자열 자료형 `얏하핫!`은 `하치와레!`로 변경되어 이전 표기를 쓰면 안내 오류가 납니다.

## 명령어

프로젝트 폴더 안에서 실행합니다.

```powershell
py -m usagi --version
py -m usagi check examples/input_plus_one.usagi
py -m usagi emit-c examples/input_plus_one.usagi -o build/input_plus_one.c
py -m usagi build examples/input_plus_one.usagi -o build/input_plus_one.exe
py -m usagi run examples/input_plus_one.usagi
```

| 명령 | 동작 |
|---|---|
| `check` | 소스 문법·변수 범위·자료형 검사. Clang 불필요 |
| `emit-c` | 런타임을 포함한 독립적인 C11 파일 생성. Clang 불필요 |
| `build` | Clang 컴파일·링크 후 실행 파일 저장 |
| `run` | 임시 폴더에서 빌드·실행하고 종료 시 임시 파일 정리 |

`-o`를 생략하면 `emit-c`는 소스 옆에 `.c`, Windows의 `build`는 `.exe`를 만듭니다. 입력 소스 자체를 출력 경로로 지정하면 거부합니다. 빌드 실패 시 기존 실행 파일은 보존되므로, 실패한 뒤 남아 있는 `.exe`는 이전 빌드일 수 있습니다.

Clang 탐색 순서는 `--cc`, 환경 변수 `USAGI_CC`, `PATH`, Visual Studio 설치 정보(`vswhere`) 순입니다. 별도의 PATH 변경 없이 설치된 Build Tools를 찾습니다. 수동 지정 예:

```powershell
py -m usagi build examples/input_plus_one.usagi -o build/input_plus_one.exe --cc "C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\VC\Tools\Llvm\x64\bin\clang.exe"
```

위 경로는 이번 컴퓨터의 설치 경로입니다. `--cc`에는 `clang-cl.exe`가 아닌 `clang.exe`를 지정합니다. C 컴파일은 60초 제한을 두고, 대화형 프로그램 입력에는 시간 제한을 두지 않습니다. 실행 중단은 Ctrl+C입니다.

선택적으로 `py -m pip install -e .`로 설치하면 `usagic` 명령도 등록됩니다. 기본 사용에는 필요하지 않으며, 이 설치 경로는 이번 검증 범위에 포함하지 않았습니다.

## 구현된 문법

| 기능 | 표기 또는 규칙 |
|---|---|
| 메인 시작 / 정상 종료 | `우사기!` / `!우사기` |
| 함수 시작 / 종료와 반환 | `우나! 하치와레: 함수명` / `우~나! 반환식` |
| 함수 호출 | `하치와레: 함수명 우라! 우라라!` |
| 문장 끝 | `야하!` |
| 블록 | `우랏!` … `우라랏!` |
| 계산 괄호 | `우라!` … `우라라!` |
| 정수 선언 | `얏! 하치와레: 야 뿌 야하!` |
| 실수 선언 | `핫! 하치와레: 야 뿌.뿌릇 야하!` |
| 사용자 이름 | `하치와레: 이름`, 여러 단어 허용. `야` 반복 변수명만 접두사 생략 가능 |
| 문자열 선언 | `하치와레! 하치와레: 내용 하치! 안녕 와레! 야하!` |
| 재대입 | `하치와레: 야 야~하! 뿌르 야하!` |
| 더하기 / 빼기 | `하!` / `하아!` |
| 곱하기 / 나누기 / 나머지 | `하핫!` / `푸루!` / `푸루루!` |
| 숫자 입력 | `냠? 하치와레: 야 야하!` |
| 문자열 입력 | `하아? 하치와레: 내용 야하!` |
| 출력 | `우~라~ 하치와레: 야 하! 뿌르 야하!` |

지원 문법과 수치·범위·입출력·오류 정책은 표준 문서의 **v1.1 실행 규칙**으로 확정했습니다. 함수·이름 규칙과 사용자가 채택한 제어문·먹이기 인자를 구현했습니다.

토큰 사이는 공백·탭·줄바꿈으로 구분합니다. 예를 들어 `뿌야하!`처럼 서로 다른 토큰을 붙여 쓰면 오류입니다. 숫자 내부의 `~` 생략과는 다른 규칙입니다. 소스는 UTF-8이며 UTF-8 BOM도 허용합니다. 주석 문법이나 문자 정규화는 지원하지 않습니다.

곱하기·나누기·나머지를 더하기·빼기보다 먼저 계산합니다. 같은 우선순위는 왼쪽부터 계산합니다. 괄호로 순서를 바꿀 수 있습니다.

변수는 초기값과 함께 선언합니다. 같은 블록에서 같은 이름을 다시 선언할 수 없고, 중첩 블록에서는 바깥 이름을 가리는 선언을 허용합니다. 초기값은 새 변수가 등록되기 전에 평가하므로, 같은 이름의 바깥 변수가 있다면 그 값을 참조합니다. 블록 밖에서는 내부 변수에 접근할 수 없습니다.

메인과 일반 함수는 중괄호 없이 시작·종료 표식으로 본문을 구분합니다. `우랏!`·`우라랏!`은 함수 안에 별도 변수 범위가 필요할 때 사용하는 블록으로 유지합니다. 열린 내부 블록을 닫은 뒤에 함수를 종료해야 합니다. 함수 종료 표식 뒤에 본문 문장을 이어 쓸 수 없습니다.

## 세 반응 분기와 반복문

제어문도 중괄호 없이 시작·끝 소리로 본문을 묶습니다. `갸웃?`은 숫자의 부호에 반응하고, `우쨔?`은 정수 횟수만큼, `푸루룻!`은 마지막 조건이 양수인 동안 반복합니다.

### 세 반응 분기

```text
우사기!
    얏! 야 뿌 야하!
    냠? 야 야하!
    갸웃? 야 하아! 뿌릇
        야호!
            우~라~ 하치! 다섯보다 많아! 와레! 야하!
        하아...
            우~라~ 하치! 정확히 다섯! 와레! 야하!
        우우...
            우~라~ 하치! 다섯보다 적어! 와레! 야하!
    갸웃!
!우사기
```

`야 - 5`를 한 번 계산해 양수는 `야호!`, 0은 `하아...`, 음수는 `우우...` 본문을 실행합니다. 필요한 반응만 적을 수 있고 순서는 자유입니다. 반응은 최소 하나가 필요하며 같은 반응을 두 번 쓸 수 없습니다. 맞는 반응이 없으면 다음 문장으로 갑니다. 실수도 조건으로 사용할 수 있고 -0.0은 0 반응입니다. 문자열은 조건으로 사용할 수 없습니다. 말줄임표는 점 세 개(`...`)입니다.

### 박자 반복과 남은 횟수

```text
우사기!
    우쨔? 뿌르르르
        우~라~ 뿌야! 야하!
    우쨔!
!우사기
```

출력은 `3`, `2`, `1`입니다. `우쨔?`는 시작할 때 횟수를 한 번 계산해 보관합니다. 본문에서 그 식의 변수를 바꿔도 이미 시작한 반복 횟수는 바뀌지 않습니다. 횟수는 정수만 허용하고 0이면 건너뛰며 음수는 실행 오류입니다. 실수는 자동으로 정수로 바꾸지 않습니다.

`뿌야!`는 가장 안쪽 횟수 반복의 남은 횟수이며 읽기만 가능합니다. 중첩 반복이 끝나면 바깥 횟수를 다시 가리킵니다. 안쪽 `우쨔? 뿌야!`는 바깥 남은 횟수로 새 반복을 시작합니다. `뿌야!`는 같은 함수에서 문법상 둘러싼 `우쨔?`가 있어야 하며, 호출한 다른 함수에는 전달되지 않습니다.

### 마지막에 조건을 묻는 반복

```text
우사기!
    얏! 야 뿌 야하!
    푸루룻!
        냠? 야 야하!
        우~라~ 야 야하!
    푸루룻? 야
!우사기
```

본문을 최소 한 번 실행한 뒤 마지막 식이 양수이면 다시 실행합니다. 0이나 음수이면 종료합니다. 정수·실수 조건을 허용하고 조건은 매 차례 다시 계산합니다. 위 예제에 `2`, `1`, `0`을 입력하면 세 값을 출력한 뒤 종료합니다.

조건식에서 사용할 변수는 반복 전에 선언합니다. 본문 내부에 선언한 변수는 그 차례 안에서만 사용할 수 있고 마지막 조건식이나 반복 밖에는 보이지 않습니다. `푸루룻!`에는 남은 횟수가 없지만 바깥에 횟수 반복이 있으면 `뿌야!`로 바깥 횟수를 읽을 수 있습니다.

### 중간 탈출과 다음 차례

| 문장 | 동작 |
|---|---|
| `삐익! 야하!` | 가장 안쪽 반복을 즉시 종료. 마지막 조건식도 건너뜀 |
| `휙! 야하!` | 가장 안쪽 반복의 나머지 본문을 건너뜀 |

`우쨔?`에서 `휙!`은 남은 횟수를 줄이고 다음 차례로 갑니다. `푸루룻!`에서는 마지막 조건을 검사한 뒤 다시 실행할지 결정합니다. 분기 안에서도 사용할 수 있습니다. 같은 함수의 반복문 안에서만 허용합니다.

분기·반복 본문마다 변수 범위를 만들며 중첩할 수 있습니다. 바깥 변수에 대입한 값은 유지됩니다. 함수 종료 표식은 열린 제어문을 모두 닫은 뒤 적습니다. 일반 문장에는 `야하!`가 필요하고 시작·반응 표식에는 붙이지 않습니다. 제어문 닫는 표식 뒤의 `야하!`는 생략 가능합니다.

```powershell
py -m usagi run examples/three_reactions.usagi
py -m usagi run examples/countdown.usagi
py -m usagi run examples/repeat_input.usagi
py -m usagi run examples/skip_and_stop.usagi
```

무한 반복도 작성할 수 있습니다. `run` 실행은 Ctrl+C로 중단하며, 컴파일러는 자식 프로세스가 종료된 뒤 임시 실행 파일을 정리합니다.

## 숫자와 계산 범위

| 값 | 소스 표기 |
|---|---|
| 0 | `뿌` |
| 1 | `뿌르` |
| 2 | `뿌르르` |
| 5 | `뿌릇` |
| 6 | `뿌릇뿌르` |
| 10 | `뿌릇뿌릇` |
| 20 | `뿌르르뿌릇뿌릇` |
| 100 | `뿌르뿌르릇` |
| 123 | `뿌르뿌르릇~뿌르르뿌릇뿌릇~뿌르르르` |
| -5 | `릇뿌뿌릇` |
| 0.5 | `뿌.뿌릇` |

숫자 리터럴은 정수부 절댓값 0~999와 소수부 한 자리를 지원합니다. `~`는 백·십·일 자리 묶음 사이에서 각각 생략 가능합니다. 계수와 자리 단위 사이, 음수 접두사 뒤에는 넣을 수 없습니다. 10 자체의 축약형 외에는 십의 자리 계수 1도 씁니다. 임의로 `르`를 다섯 번 이상 늘인 표기는 지원하지 않습니다.

음수는 전체 숫자 앞에 `릇뿌`를 붙입니다. 음의 0도 허용합니다. 소수점 양쪽 값은 생략할 수 없습니다. `릇뿌`는 변수나 괄호에 적용하는 단항 연산자가 아닙니다.

소스 표기 범위와 실행 중 값의 범위는 다릅니다.

- 정수는 -9,223,372,036,854,775,808부터 9,223,372,036,854,775,807까지입니다. 계산과 입력 결과가 범위를 넘으면 오류입니다.
- 실수는 C `double`입니다. 이번 Windows x64 환경에서는 IEEE 754 64비트 부동소수점입니다. 십진 소수를 항상 정확히 표현하지는 못합니다.
- 반환형은 반환식의 자료형에서 추론합니다. 함수가 반환한 값 또는 다른 식을 변수에 넣을 때는 그 변수의 선언형으로 자동 변환합니다.
- 정수·실수 혼합 계산은 실수로 승격합니다. 정수→실수 변환을 허용하지만 큰 정수는 정밀도가 줄 수 있습니다. 실수→정수 변환은 0 방향으로 소수 부분을 버립니다. 예: 3.9 → 3, -3.9 → -3. 변환 가능 범위를 넘으면 실행 오류입니다.
- 식을 계산한 뒤 대입 변환합니다. 정수 나눗셈 결과를 실수 변수에 대입한다고 해서 나눗셈이 실수 계산으로 바뀌지는 않습니다. 함수 반환형도 대입받는 변수형에 따라 바뀌지 않습니다.
- 정수 나눗셈은 0 방향으로 버립니다. 예: -7 / 3 = -2, -7 % 3 = -1. 나머지는 정수끼리만 허용합니다.
- 0으로 나누기, 정수 최솟값을 -1로 나누거나 나머지를 구하기, 정수 오버플로는 실행 오류입니다.
- 실수 계산 결과가 NaN·무한대이면 오류입니다. 계산 중 언더플로는 플랫폼의 `double` 결과(0 또는 비정규 수)를 따릅니다. 입력 변환이 `ERANGE`를 보고하면 오류입니다.

## 정수 배열·숫자 입력·개행

```usagi
우사기!
    얏! 하치와레: 사람수 뿌 야하!
    핫! 하치와레: 평균점수 뿌 야하!
    냠? 하치와레: 사람수, 하치와레: 평균점수 야하!

    야얏! 하치와레: 사람수 하치와레: 점수 야하!
    뿌 하치와레: 점수 야~하! 하치와레: 평균점수 야하!
    우~라~ 뿌 하치와레: 점수 야하!

    하치와레! 하치와레: 인사 하치! 와레! 야하!
    하아? 하치와레: 인사 야하!
    우~라~ 하치와레: 인사 야하!
    우~라~ 하치! 안녕우이!우사기! 와레! 야하!
!우사기
```

첫 줄에 `3 82.5`, 다음 줄에 `우사기 좋아`를 입력하면 `82`, `우사기 좋아`, `안녕`, `우사기!`를 각각 한 줄로 출력합니다. `야얏!`은 크기·이름 순서로 선언하며 0 초기화·0 기반 인덱스를 사용합니다. 계산한 인덱스는 기존 괄호로 묶습니다. 배열 전체 복사·인자 전달·반환은 미지원입니다.

숫자 줄을 모두 소비한 뒤 문자열 입력을 하면 다음 실제 줄을 읽습니다. 그 줄이 빈 줄이면 빈 문자열을 받습니다. 숫자 줄에 읽지 않은 값이 남은 채 문자열 입력으로 전환하면 실행 오류입니다. `우이!`는 리터럴 안에서만 개행으로 바뀌고 입력 문자열에서는 그대로 보존합니다.

**0.5에서 변경:** 숫자 변수에 사용하던 `하아?`를 `냠?`로 바꾸세요. `하아?`는 문자열 전용입니다.

## 입출력과 오류

숫자 변수에는 `4`, `-5`, `3.2`처럼 일반 십진수로 입력합니다. 우사기 숫자 발음으로 입력하지 않습니다. `냠?`는 공백·탭·줄바꿈으로 구분된 숫자를 대상 자료형에 따라 하나씩 읽습니다. 대상이 여러 개면 쉼표로 구분합니다. `하아?`는 문자열 변수 하나에 한 줄을 입력합니다. 정수 입력은 부호와 숫자만 허용하며, 실수 입력은 소수 및 `1.25e2` 같은 지수 표기도 허용합니다. 소스의 소수부 한 자리 제한은 **실행 중 입력에는 적용되지 않습니다**.

입력 한 줄은 최대 4,095바이트입니다. 숫자 입력은 빈 줄을 건너뜁니다. 잘못된 숫자 토큰, NaN·무한대·16진수, 정수 대상의 소수·지수 입력은 오류입니다. 문자열 변수는 일반 글과 앞뒤 공백·빈 줄을 보존합니다. 모든 입력에서 NUL, 길이 초과, 입력 종료는 오류이며, 숫자는 범위도 검사합니다. 파일·파이프의 마지막 줄은 개행 생략을 허용합니다. 우~라~는 한 값과 줄바꿈, 우~라!는 한 값만 출력하며, 실수는 유효 숫자 최대 15자리(`%.15g`)로 출력합니다. 따라서 실수 1.0은 `1`로 출력될 수 있습니다.

문자열 파이프·파일 입출력은 UTF-8 바이트를 사용합니다. Windows 콘솔에서는 Unicode 콘솔 API로 문자열 입출력을 처리합니다. 자동 테스트는 UTF-8 파이프 입력·출력을 검증했으며 실제 VS Code 터미널의 대화형 한글 입출력은 별도 확인이 필요합니다.

문법 오류는 `파일:줄:열`과 한국어 설명을 보여 줍니다. 실행 오류도 원본 `.usagi` 파일과 줄·열을 표시하며, C 런타임 메시지는 현재 영어입니다. 실행 파일에 원본 경로 문자열이 들어가지만 실행 시 원본 파일을 읽지는 않습니다.

| 종료 코드 | 의미 |
|---|---|
| 0 | 성공 |
| 1 | 소스 읽기·컴파일·빌드 실패 |
| 2 | 실행 중 수치·입출력 오류 (`argparse` 명령 사용 오류도 2) |
| 130 | CLI에서 Ctrl+C 중단을 처리한 경우 |

2026-10-16, Python 3.12.14 / Clang 22.1.3 / Windows x64에서 **123개 테스트 통과, 건너뛴 테스트 없음**. Clang이 없는 환경에서는 네이티브 실행 관련 테스트가 건너뛰어집니다.

검증에는 네이티브 실행 파일 67개와 CLI 실행 테스트가 포함됩니다. 인자 개수·매개변수 범위·값 복사·중첩 호출·평가 순서·숫자 변환과 JSON 진단을 추가 검증했습니다. 기존 분기·반복·숫자·문자열·함수·변수명과 중단 정리 테스트도 통과했습니다. C 옵션은 `-std=c11 -O2 -Wall -Wextra -Werror`입니다. `tests/`에서 재현할 수 있습니다.

## 아직 지원하지 않는 것

문자형 `얏핫!`은 아직 미지원입니다. 문자열 일반 이스케이프·여러 줄 리터럴·문자열→숫자 변환, 소스의 여러 자리 소수부, 1,000 이상의 자리 단위, 비교·논리·일반 단항 연산자, 여러 겹 반복 탈출, 조건부 조기 반환, 기본·가변 인자·재귀·중첩 함수·반환값 없는 함수, 주석은 구현하지 않았습니다. 별도 VS Code 확장에서 구문 강조와 코드 조각을 제공합니다.

## 소스 구성

- `usagi/numbers.py`: 숫자 표기 검증. 유한한 표기 사전을 만들며 충돌을 검사합니다.
- `usagi/compiler.py`: 토큰 분석, 구문 트리, 범위·자료형 검사, C 생성.
- `usagi/runtime.c`: 범위 검사, 값으로 복사되는 문자열, 숫자·문자열 입출력. 생성된 C에 포함됩니다.
- `usagi/toolchain.py`: Clang 탐색, 제한 시간과 결과 파일 교체를 포함한 빌드.
- `usagi/cli.py`, `usagi/__main__.py`: 명령행 인터페이스.
- `examples/`, `tests/`: 예제와 자동 검사.

Linux/macOS용 분기는 포함되어 있지만 해당 플랫폼에서 빌드·실행을 검증하지 않았습니다.

## v1.1 문자열과 출력

`우~라! 식 야하!`는 줄바꿈 없이 출력합니다. `문자열 시사! 문자열`은 연결,
`모몽가! 우라! 숫자식 우라라!`는 숫자를 문자열로 바꿉니다. 연결한 값도 UTF-8 4,095바이트 한도를 따릅니다.
[99병의 맥주 예제](examples/99_bottles.usagi)에 세 문법을 함께 사용했습니다.
